# 真盲测集（blind_test）—— 与 218 案语料**隔离**

> 建立于 2026-09-17。目的：**给"真实预测"一个数字**。

## 1. 为什么必须独立于 218 案

| | 218 案语料（`engine/shuzheng_real_cases.json`） | 本库 `blind_test` |
|---|---|---|
| 案例来源 | 古籍《断案疏正》 | **真实用事/占断** |
| 规则来源 | **同一批古籍**（规则取自古籍） | —— |
| 时序 | 已知结局的**历史**案例 | **预测在前、结果在后** |
| 用途 | 测**保真度**（还原古人断法） | 测**预测力** |
| 曾被用于调参？ | ✅ 是（涉害/别责/青龙丑…反复投票） | ⛔ **禁止** |

⇒ 218 案的 89.4% 实质是「83.1% 语料底子 + 6.3pp」（见 `docs/reports/_盲测与真实预测差距盘点.md`）；
**真正未知的是本库的比率**。

## 2. 🔴 四条红线（违反即失去意义）

1. **禁止事后补记"预测"** —— 必须**结果未知时先记**。事后补记 = 退化成 218 案同类。
2. **与 218 案严格隔离** —— ⛔ 不得用本库样本参与规则调参、A/B 投票、阈值搜索。
3. **不得 `import stock_dashboard`** —— 该模块 import 即起「事件起课」心跳线程（违「非起课窗口绝不起课」）。
4. **不得调写库 API** —— `/api/zeri/analyze` 会写 `leixiang_kb`；记账只写本目录文件。

## 3. 记录格式（`predictions.jsonl`，每行一条 JSON）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ 自动 | `BT-YYYYMMDD-NNN` |
| `created_at` | ✔ 自动 | 记账时间（ISO8601 +08:00） |
| `prediction` | ✔ | **吉 / 凶 / 平** —— 盲测的核心是"先表态" |
| `kind` | | `择日` ｜ `占断` |
| `source` | | `人工起课` ｜ `天机起课` |
| `event_date` | | **用事日**（择日）或占断对象日 |
| `shichen` / `zhanlei` / `mountain` | | 时辰／占类／坐山 |
| `rizhu` / `yue_jiang` / `sanchuan` / `keti` | | 课盘关键字段（便于事后复核，可只抄主干） |
| `score` / `grade` / `trend` / `prob_up` / `prob_down` | | 引擎输出（概率字段利于后续做**校准**评估） |
| `note` | | 当时的判读要点 |
| `outcome` | 回填 | **吉 / 凶 / 平** |
| `outcome_date` / `outcome_note` | 回填 | 结果日期与事实描述 |
| `demo` | | `true` = 示例行，**不参与统计** |
| `outcome_unknown_at_created` | 🆕 | **占断类专用**：`true` = 记账时**结局未知**（见 §5.3） |

### 5.3 🆕 占断类如何满足「红线 1」（2026-10-04 补）

**红线 1（禁止事后补记）的真实语义 ＝ 「记账时*结果*是否已知」，⛔ 不是「记账日 < 用事日」。**

| 类 | 预测对象 | 记账时点 | `verify` 口径 |
|---|---|---|---|
| **择日** | 用事日**当天/之后** | 须早于行用日 | `created_at ≤ event_date` |
| **占断** | 一个**正在发生**的事（故 `event_date` 常＝起课日或更早） | 起课后即刻（**结局仍未知**） | 晚记账 + 声明 `outcome_unknown_at_created=true` |

⇒ 只按「记账日晚于用事日」判违规，**会误杀占断类**。故 `verify` 已放行显式声明者，
并单独列印提示（`ⓘ 另 N 条晚记账但已声明记账时结局未知`）。

🔴 **声明使用纪律**：`outcome_unknown_at_created` **只在结果确实未知时可填**，
由人填、不得用作掩盖事后补记的后门；一旦 `outcome` 已回填，该字段不再有意义。


## 4. 用法

```bash
# ① 起课后立刻记（结果未知）—— 只抄 5 个关键字段即可，越省事越能坚持
python _blind_log.py add --kind 择日 --event-date 2026-09-20 --shichen 卯 \
    --zhanlei 婚嫁 --mountain 卯 --prediction 吉 --score 75 --grade 吉 --note "课吉，末传空亡"

# ② 结果出来后回填（只填结果，不改预测）
python _blind_log.py fill --id BT-20260917-001 --outcome 吉 --note "如期成婚"

# ③ 看进度与成绩
python _blind_log.py list
python _blind_log.py stat      # 自动并列「朴素基线（全判凶）」＋真实增量＋分组

# ④ 🆕 自动记账（**推荐入口** —— 引擎自算课盘与预测，省掉手抄；闭环能否坚持的关键）
python _blind_log.py auto --event-date 2026-11-20 --shichen 辰 --mountain 寅 \
    --zhanlei 开业 --note "……"        # 加 --dry-run 只算不落盘
# ⑤ 🆕 到期提醒（列出已过用事日、仍未回填的）
python _blind_log.py due
# ⑥ 🆕 隔离自检（红线 1/2：是否混入 218 案、是否有事后补记）
python _blind_log.py verify
# ⑦ 🆕 查「结果判定标准」（**回填前必看** —— 2026-09-30 拍板 C 方案：按事类定指标）
python _blind_log.py rubric --zhanlei 开业
```

> ⓘ `auto` 只调 `engine.*`（实测 import **零线程副作用**），⛔ 不碰 `stock_dashboard`；
> 预测默认取引擎判断，可用 `--prediction` 覆盖（人工表态优先）。
> 🆕 `auto` 同时**盲记引擎自报应期**（`yingqi_text/struct/grain`）—— 见 §5.2。

# ⑧ 🆕 应期命中回填（**独立于吉凶**的第二维度）
python _blind_log.py yingqi --id <id> --actual 2027-04-02 --hit 命中 --note "4月初动"
#   --hit 三档：命中（粒度+时点吻合）｜偏移（事发了但时点不符）｜未应（应期内未发）

## 5. 何时记 / 何时填

- **记**：择日定档后、或占断结论出口时 **立刻**记（哪怕只填 `prediction` 一项）。
- **填**：课的**应期**（§5.2）之后回访结果。间隔可达数月甚至数年 —— **未回填也是正常状态**（`stat` 会单列）。
- ⓘ 本库的价值**全在时间上**：今天记 1 条，一年后才有 1 条可用样本。**越早开始越好。**

### 5.2 🔴 应期（取代固定「观察窗」）—— 2026-09-18 拍板

**观察窗不由事类固定** —— **应期长短本就由课定**。
铁证：疏正 219 案应期跨度极大：**几个时辰**（失物「申牌后寻得」）／**几天**／**几个月**／
**几年**（「不出六年」「十一年」「十六年」）／**一辈子**（终身类）。
⇒ 对同一个「安葬」，固定 3 年或 1 年**都是伪精确**。

**双轨**：

| 轨 | 内容 | 字段 |
|---|---|---|
| **应期预测**（记账时） | 引擎自报应期（支数/月建/太岁/旬空填实/合冲/速迟 共 7 法，粒度日~年）**盲记** | `yingqi_text` / `yingqi_struct` / `yingqi_grain` |
| **实测应期**（回访时） | 实际何时发／是否发 | `yingqi_actual` / `yingqi_hit`（命中/偏移/未应） |

- 🔴 **粒度＝引擎自报**，⛔ 非人工裁定；取「实测最小」（日/旬/月/年）。
- **兜底回访窗**（**仅提醒、⛔ 不判定**）：按**原文上限 × 3**（通解_上 L3414
  「日上发用应在旬内；辰上发用应在一月；得岁不出岁…」）⇒
  **时/旬→30 天｜月→90 天｜年/缺→365 天**（2026-10-02 校准，原 30/90/180/365 系拍的）。
  ⚠️ 实测位置法档「在上限内」满足率 **69.6%（16/23，n 小）** ⇒ 窗只是**操作提醒**，⛔ 非应期预测。
- ⚠️ **兜底窗到期 ≠ 必须定档** —— 判定时点以课的应期为准（用事人自判）。
- ⓘ 长期复核（婚嫁 3 年存续、阴宅 3 年渐旺）仍可**另立档案**，不混入主统计。

## 6. 统计口径纪律

`stat` 输出已内置：
- **准确率必须并列「朴素基线（全判凶）」**（218 案上这条基线＝83.1%，只报准确率会严重高估）；
- 输出**真实增量（pp）**与**混淆矩阵**；
- 按 `kind` / `zhanlei` 分组。

⚠️ **样本量纪律**：`n < 10` 时**不得**据本库改评分链（守既有红线）；先积累。
