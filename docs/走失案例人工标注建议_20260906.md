# 12 条走失案例人工标注建议

> 针对 `data/daliuren_shuzheng_cases.json` 中 12 条"占走失"案例（SZ-008/SZ-057/SZ-072/SZ-087/SZ-112/SZ-127/SZ-142/SZ-157/SZ-172/SZ-187/SZ-202/SZ-217）
> 生成日期：2026-09-06

## 一、为什么不适合自动回测（现状诊断）

### 1. 数据类型问题——非"失物类神法"案例

这 12 条是**"走失人"占**（占走失的人能否回来/何时归），其断法依赖**三传时序 + 六亲眼色 + 应期**（如 SZ-008"初传寅木动人在东方，中传巳火被人收留，末传申金平安归来"），**不是** `judge_lost` 的"失物类神 W1-W4 判法"（类神在传/加日辰/受克被杀）。用失物判法回测走失案例，本质是**测错对象**。

### 2. 数据模板化严重

| 特征 | 统计 |
|---|---|
| 三传同为"巳寅亥" | 11/12 条（SZ-008 除外）|
| 断语句式雷同 | 11/12 条（"初传巳火主吉庆/中传寅木主顺利/末传亥水主成功"）|
| 应期雷同 | 11/12 条（"巳月应吉，寅月事成，亥月成功"）|
| 天将解释提取无序 | 青龙/玄武 2 将分布不明（初/中/末归属无法自动对应）|

**结论**：这批案例疑似**批量生成/模板填充**数据（课体重复、断语句式复制），非古籍原案例多样性，作为回测基准价值低且会污染评估。

### 3. 天将顺序无法自动恢复

三传解释文本（如"初传巳火乘青龙，中传寅木乘青龙，末传亥水乘玄武"）中有明确顺序，但**没有结构化字段**保存（初传天将/中传天将/末传天将）。自动正则只能提取"出现过的天将集合"（`['青龙','玄武']`），无法重建每传具体乘将。

## 二、人工标注建议

### 建议 1：先甄别数据来源（优先级最高）

**先确认这 12 条是否古籍真实案例**（对照《大六壬断案疏正》原文）：
- 若为**模板化生成** → 整个剔除出叙事引擎验证集，不标注（避免污染）
- 若为**古籍真实案例** → 按下方结构标注

### 建议 2：为每条补充结构化字段（若保留）

在案例 JSON 中补 4 个字段：

```json
{
  "leishen": "初传寅木为类神（人/财）",   // 类神是什么（人或物）
  "判法类型": "走失人吉凶",               // 或"失物类神"
  "天将分布": {"初传": "青龙", "中传": "朱雀", "末传": "太阴"},
  "结果吉凶": "吉"                        // 断语结论（吉/凶/平）
}
```

- `leishen`：标注本例类神对应（如 SZ-008 以寅木为财/人）
- `天将分布`：把三传解释文本中的天将**逐传对应**（如 SZ-008：青龙/朱雀/太阴）
- `结果吉凶`：从断语提取终局（如 SZ-008 断"平安归来"→吉）
- `判法类型`：区分"走失人吉凶"vs"失物类神"，决定走哪套引擎回测

### 建议 3：为走失人判法单独建回测

走失人判法（三传时序+六亲）应**新建独立判法函数**（如 `judge_lost_person`）而非套用失物 `judge_lost`：
- 初传动 → 方向/移动（寅=东方）
- 中传官鬼 → 被收留/有动静
- 末传生扶 → 平安归来
- 应期：初传静、中传动、末传应

标注完成后可建 `backtest_lost_person.py` 复用已有三传/应期字段。

## 三、标注工作量与优先级

| 事项 | 工作量 | 优先级 |
|---|---|---|
| 甄别 12 条数据来源（是否古籍）| 低（查原文对照）| **P0** |
| 若保留：补 leishen/天将分布/结果吉凶 | 中（12 条 × 3 字段）| P1 |
| 若剔除：无需标注 | 零 | — |
| 新建走失人判法 + 回测 | 高（新判法函数）| P2 |

## 四、建议执行路径

1. **P0**：先答"这 12 条是不是古籍原文"——是模板生成就整批剔除，是真实案例才值得标注
2. **P1**：标注后即可接入"走失人判法"（新建函数）回测
3. **P2**：失物类神法（judge_lost）的自动回测继续用已标注的古文案例（§182/186/180/187/191/174 等）+ 扩展古籍原案例
