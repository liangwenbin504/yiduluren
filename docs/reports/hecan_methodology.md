# 多条件合参方法论（2026-08-18）

## 一、方法（三层架构，推广至全部古断语）

```
L1 硬规则层 = liuchen_engine 现有单/双条件规则（已过 632 全库验证，不动）
L2 合参规则层 = hecan_engine：断语"条件集合→结论"，全条件命中才触发，
                叙事层输出（不参与评分，零回退）
L3 规则候选库 = data/hecan_rules.json：正议体提取的候选+验证状态
                门槛：全中样本≥3 且方向一致率≥80% 才升入 L2
```

**推广价值**：任何古断语（邵公/陈公献/王牧夫/祝泌/叶飘然…）都按
"断语→条件集合→结论"结构化入库。合参验证在**入引擎之前**定量把关，
把"落地后回测撞出误伤再回滚"改为"验证不过直接否决"。

## 三、方法论结论

1. **合参验证是"不臆造"的可执行形态**：规则必须满足"原文条件集合+全中+方向一致率达标"
   三关才能进引擎，任何一条不过就留在候选库。
2. H001 失败原因：条件集仍不完整（缺"非刑害/非诉讼"否定条件），说明正议体的合参
   往往含**否定条件**（"非X"）——后续提取需把断语中的排除项也结构化。
3. 现有 6 条样板规则中 H003/H004/H006 已验（L1 同条件，632 零回退）、
   H001 否决、H002/H005 样本不足待积累。
