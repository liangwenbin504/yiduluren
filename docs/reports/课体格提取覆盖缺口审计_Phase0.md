## 0. 结论先行（TL;DR）

1. **活动管线的课体格提取确实"粗糙"，且比想象的更严重**：
   - `KETI_VALENCE`（课体吉凶表）共 **53** 个条目，但活动管线（`engine/liuren_keti_bifa.py`）**只有 9 个课体是确定性判定的**（八专/元首/重审/遥克/知一/昴星/独足/返吟/伏吟）；外加 1 个毕法（铸印，三传巳戌卯）经毕法路径确定性判定。
   - 其余 **43 个课体条目没有任何确定性判定**——要么靠"扫描古例断语原文里是否点名该课体"（文本扫描，含事后解释泄漏，且仅古例有原文时有效，股票路径完全用不到），要么根本不计算。
   - `BIFA_VALENCE`（毕法吉凶表）共 **35** 个条目，除铸印外 **34 个**同样只靠文本扫描或死代码。

2. **更关键：项目里早已存在"完整且（疑似）正确"的课格/毕法判定实现，却几乎全部被弃用、未接入活动管线**：
   - `engine/bifa_detector.py` —— 一个**完整的 ~100 条毕法赋规则检测器**（`_check_rule_1` … `_check_rule_100`），却**从未被诚实基线或股票路径 import**（已用 grep 确认）。
   - `engine/special_kege.py` —— 约 16 个特殊课格检测器（游子/斩关/铸印/斫轮/轩盖/三奇/闭口/罗网…），**未被活动管线 import**。
   - `engine/daliuren_kege_analyzer.py`、`engine/liuren_64ke_knowledge.py` —— 同样未被活动管线 import。
   - `zongmen/` 目录 —— 独立的 64 课经知识库 + 720/8640 课体匹配器，**完全未接线**。

3. **九宗门专项（最该打好的基础）：权威实现已存在，活动探针却走了样**。
   - 权威四课三传计算器 `engine/sike_sanchuan_engine.py` **已经实现完整、带优先级与比用/涉害的九宗门**（含文档化 bug 修复，优先级：伏吟→反吟→贼克[重审优先于元首，含比用/涉害]→遥克→昴星→别责→八专）。
   - 活动探针 `liuren_keti_bifa.derive_jiuzongmen` 是其**简化重写**，且引入了确定性的 bug（见 §5）。
   - 因此"九宗门重提取"的正确做法不是从零重造，而是**对齐权威引擎 + 古籍校验 + 正/反例单测**，这比重新发明可靠得多。

## 2. KETI_VALENCE 覆盖缺口表（脚本核对结果）

**总数**：`KETI_VALENCE` = 53 条；`BIFA_VALENCE` = 35 条。

### 2.1 确定性判定的课体（9，活动管线内）
八专、元首、重审、遥克、知一、昴星、独足、返吟、伏吟
- 来源：`derive_jiuzongmen`（八专/元首/重审/遥克/知一/昴星）、`derive_sanchuan_kege`（独足/返吟/伏吟，返吟/伏吟需天地盘）。
- ⚠️ 这 9 个里 `derive_jiuzongmen` 本身有 bug（见 §5），所以"判定了"≠"判定对"。

### 2.2 确定性判定的毕法（1，活动管线内）
铸印（三传地支集合 == {巳,戌,卯}，`build_keti_duanyu` L461 硬编码）。

### 2.3 未确定性判定的课体（43）
三交、三光、三奇、三阳、乘轩、乱首、从革、佚女、全局、六仪、冲破、别责、励德、地网、天狱、天网、官爵、富贵、寡宿、度厄、得禄、德入、悬胎、拔茅、斩关、斫轮、无禄、曲直、涉害、润下、游子、炎上、盘珠、稼穑、绝嗣、芜淫、财德、赘婿、轩盖、**铸印(已在毕法路径判定，课体条目本身不进 keti 桶)**、闭口、食禄、鬼墓、龙德。

> 其中 23 个同时存在于 `BIFA_VALENCE`（三交/三奇/乘轩/乱首/六仪/冲破/励德/地网/天网/官爵/富贵/得禄/德入/悬胎/拔茅/斩关/游子/芜淫/财德/赘婿/闭口/食禄/鬼墓）。这些名称在古例有断语原文时，可能被 `scan_text` 文本扫描"碰巧"命中——但那是**泄漏性、非确定性**的，且对股票路径（无原文）完全无效。

### 2.4 结论
活动管线对 53 个课体只确定性覆盖了 9（约 17%）；对 35 个毕法只覆盖了 1（约 3%）。这是"粗糙"的量化证据。

## 4. 九宗门专项：基础已存在，活动探针走样（最关键发现）

### 4.1 权威实现（已存在，疑似正确）
`engine/sike_sanchuan_engine.py` 是项目真正的四课三传计算器，其九宗门逻辑：
- L343 注释明确优先级：**伏吟 → 反吟 → 贼克(含比用/涉害) → 遥克 → 昴星 → 别责 → 八专**。
- L391 / L1473：**多课克贼，分优先级：下贼上(重审) > 上克下(元首)**。
- L1468-1471：贼克法完整链 = ①重审优先于元首 → ②多候选用比用(阴阳比) → ③仍多则用涉害 → ④比用无候选取首。
- L1303-1306 自述已修复的 bug：别责顶层优先于贼克、遥克优先于八专/别责等。

### 4.2 活动探针 `derive_jiuzongmen`（`liuren_keti_bifa.py` L238-302）的 bug
与权威实现逐条对比，发现确定的缺陷：

| 编号 | Bug | 代码位置 | 权威正确做法 |
|---|---|---|---|
| A | **元首优先于重审**（先判 `has_shangke`→元首，再判 `has_xiake`→重审） | L275-280 | 应为**重审(下贼上)优先于元首(上克下)** |
| B | **缺失比用(知一)/涉害/见机/缀瑕**的独立判定——多克时直接返回首克 | 整体 | 多候选应先比用，再涉害 |
| C | **八专位置错误**：先判 `八专` 再判贼克（L253） | L253 | 八专应在**最末**（无克贼、无遥克、干支同位时） |
| D | **别责完全未处理**：`KETI_VALENCE` 有 '别责':0，但活动管线从不判定它（仅文本扫描可能命中） | — | 应实现：四课不全(两课相同)→别责 |

> 注：A/B 是**确定性标签错误**（元首 +1 vs 重审 −1，会翻转个别案例的预测），且会污染诚实基线中涉及"四课同时含上克下与下克上"的古例。这正是用户所担忧的"基础打不好、上层全错"的具体实例。

### 4.3 建议的九宗门处理方针
**不要从零重造**——`sike_sanchuan_engine` 已是权威源。正确动作：
1. 把活动探针的九宗门判定**改为直接复用/对齐** `sike_sanchuan_engine` 的 `课体`/`起法` 输出（它已产出 '元首课'/'重审课'/'涉害课'/'见机格'/'昴星课'/'别责课'/'八专课'/'伏吟课'/'反吟课' 等标准名）。
2. 用古籍原文 + 正/反例单测**校验**这套权威实现（而非重写）。
3. 修复 `liuren_keti_bifa` 与权威名称的映射（如 '元首课'→'元首'、'重审课'→'重审'），并入 `KETI_VALENCE` 取分。
4. 补齐 涉害/见机/缀瑕/别责 在 `KETI_VALENCE` 的吉凶分值（目前 涉害=-1、别责=0，见机/缀瑕缺失）。

## 5. 64 课经知识库接线缺口 + 数据源可靠性警示

- `zongmen/pdf_extract/64_ke_full/` 中的 64 课经原文是**通过 OCR/LLM 从 PDF 自动抽取**的。这与之前 Corpus-B（疏正）数据危机同源——自动抽取存在**逐字重复模板、循环论证、损坏输入**风险。
- 因此：64 课经里**关键课体（殃咎、二烦、三交、芜淫、乱首、赘婿、斩关、铸印…）的判定规则与吉凶赋值，必须用古籍页图直接核验**，不能轻信自动抽取产物。
- 行动建议：优先把 `liuren_64ke_knowledge.py` 的 `LIU_SHI_KETI`（已人工整理、含定义/宜忌/吉凶）作为吉凶表来源，而非依赖 OCR 原文做规则。

## 6. 提出的"逐课重提取"模板（待从九宗门起首）

每一课（或每一组同源课）交付**四件套**，且**强制可测**作为唯一可靠防线：

1. **古籍原文 + 出处**：该课体的经典定义、起例，标注《六壬大全》/《毕法赋》/《壬归》具体卷目与条目。
2. **精确判定实现**：从盘面（四课/三传/天地盘/日干支）**确定性**推出，非代理、非文本扫描；与 `sike_sanchuan_engine` 权威逻辑对齐。
3. **正例 + 反例单测**：至少 1 个必中（正例）与 1 个必不中（反例）——例如返吟以 #1048（初子末午冲但天地盘不全冲）为**反例**，以天地盘全冲盘为**正例**。单测不过不准接线。
4. **与现有 KB 差异说明**：相对 `sike_sanchuan_engine` / `liuren_64ke_knowledge` / `bifa_detector` 的异同，说明为何改/不改。

**流程**：每批（建议按"九宗门 → 三传课格 → 毕法赋 → 64 课经分组"）先交四件套 → **用户审核** → 通过后再接线到活动管线 → 跑诚实基线看 M3 影响。
