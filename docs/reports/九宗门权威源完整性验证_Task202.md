## 3. 发现的 BUG：八专被别责吞掉（原生，非误改）

### 3.1 量化证据（`_diag_bazhuan.py`）
- 引擎按自身定义（`干寄宫 == 日支`）识别出的**八专日**共 5 个：`甲寅、丁未、己未、庚申、癸丑`（均为有效干支同位日），×12月×12时 = **720 课**。
- 这 720 课的实际去向：
  - 贼克法 144、涉害法 384、伏吟法 48、伏吟有贼克 12
  - **别责法 132**（本应判为八专）
  - 遥克法 0
- `is_bie_ze=True` 的课共 **2640**，但真正落到别责法的只有 264 —— 因为 `_is_bie_ze` 是"四课不备"宽判定，在 `_decide_method` 里只有"无克贼/无遥克/非八专"时才返回别责。
- **根因**：`_is_bie_ze`（L826-860）把"任意两课相同"都判为别责，而八专日（干支同位）四课只有 2 课（第一课≡第三课、第二课≡第四课），也被它命中；而 `_decide_method`（L1419-1426）**先判别责、后判八专** → 八专日的无克贼/遥克子集（132 例）全被归为别责，**八专法永远返回 0**。

### 3.2 古籍印证（证明这是 BUG，不是特性）
- `e:\仪度六壬择日\yiduluren\_archive\junk\extracted_liuxiang_content.txt`（《六壬大全》起课法章，九宗门目录 L81-82 / L1193-1194）：
  > 6. 别责法 … 7. 八专法 … 8. 伏吟法 … 9. 反吟法。「这九种法则，亦称'课式'，或称'课'。」
- **八专与别责在古籍中是并列的两个独立宗门**，绝非"别责包含八专"。引擎把八专并入别责，违反古籍宗门划分。
- 同文件 L1199-1208 印证贼克优先级：`下克上→重审课，上克下→元首课，有下贼上先论` —— 与引擎一致（这部分正确）。

**修复方向（留给 Task #203 四件套）**：使八专与别责互斥 —— 二课（干支同位）归八专、三课归别责。最小改动：在 `_decide_method` 把 `is_ba_zhuan` 判断移到 `is_bie_ze` **之前**（二课必然 is_bie_ze=True，但八专更精确）；并核对/修正 `_ba_zhuan_fa`（L925-974，目前是**从未被调用的死代码**）。八专三传细则（《六壬大全》八专法页 193）本地 OCR 未含，Task #203 需用完整 PDF 或权威本补齐印证。

> 另注：引擎的八专定义（干寄宫==日支，5 日）比传统"干支比和同阴阳"狭义（传统还多 乙卯、戊辰、己巳、辛酉、壬子、癸亥、戊戌 等）。这是**第二个待定问题**，同样需古籍八专页定夺，不阻塞本次最小修复。

## 4. 用户信任的 720 报告为何不能作为九宗门验证

`docs/720 课例课体匹配报告.md`（生成于 2026-03-16）：
- **过度匹配（假阳性）**：三光课/时泰课/天恩未定课/天狱清平课 各覆盖 **100%** 全部 8640 课 —— 显然是把通用吉格套到每课，并非真实九宗门判定。
- **九宗门特殊法从未真正校验**：报告"未匹配课体 29 个"中明确列出 **别责、昴星、涉害、遥克、八专** 为"需要特殊起法/复杂判断，本次未匹配"。即用户 720 校对覆盖的恰恰是"通用吉格"，而**九宗门的核心特殊法（含本次发现的八专）根本没被验证**。
- 该报告引用的匹配器（`ke_ti_judge.py`/`batch_match_ke_li.py`/`data/720_ke_li_matched.json`）与 `jiu_zong_men_720_matcher.py`、与 root V2 引擎**都不是同一套**。

**结论**：用户"用 720 校对几好次，应该没有 BUG"的信念，对九宗门而言**证据不足**。本次 8640 全量重算才是针对 root 权威引擎的首次干净验证，并直接暴露了八专 BUG。
