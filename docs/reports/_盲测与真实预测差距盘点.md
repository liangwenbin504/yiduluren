# 系统「盲测」与真实案例预测的差距 —— 盘点（2026-09-17）

> 起因：憨爷「现在讨论一下系统预测盲测与真实案例预测结果 的差距！」
> 方法：全部数字来自**当场实测**（`engine/_honest_skill_all.py` ＋ 新探针 `_probe_signal_groups.py`），
> 不引用任何凭印象的数字。

---

## 0. 一句话结论

> **现在的「M3 = 89.4%」＝ 在一个 83.1% 的语料底子上（全判凶即得），靠 34 例吉案里判对 16 例，
> 挣到净 +6.3pp（净 13 案）。**
> **而「真实案例预测」的差距，我们**没有数字** —— 因为择日域至今**不存在真·盲测集**。**
> ⇒ **差距的最大一块不在引擎，在评估体系。**

---

## 1. 「盲测」必须拆成四种完全不同性质的指标

| 层 | 指标 | 现值 | 性质 | 能证明「预测力」吗 |
|---|---|---|---|---|
| ① **排盘正确性** | B1 三传匹配（JSON）／B2（PDF 直提） | **99.5%**／**97.8%** | **有标准答案的复现题**（原文三传） | ❌ 只能证明「起课没算错」 |
| ② **断法保真度** | 课体 **32:0**、毕法赋 **21:0** | 「全对」 | **规则取自古籍，又在古籍上考**（同源闭环） | ❌ 同源 ⇒ 高是必然 |
| ③ **吉凶方向** | M3 | **89.4%**（vs 朴素 **83.1%**） | 真实增量 **+6.3pp** | ⚠️ 弱（见 §2） |
| ④ **真实用事预测** | —— | **无** | **没有结果回填机制** | ❌ **未知** |

⛔ **把 ①②的高分与③混为一谈，是最大的认知陷阱** —— 前两者是"照着答案复现"，与"预测未来"无关。

## 2. 89.4% 的真相：净增量只有 13 案

实测混淆矩阵（207 有效案，跳过 11）：

```
{'凶->凶': 169, '吉->吉': 16, '吉->凶': 17, '吉->平': 1, '凶->平': 1, '平->吉': 1, '凶->吉': 2}
```

| 项 | 数字 | 说明 |
|---|---|---|
| 语料真值分布 | **凶 172 ／ 吉 34 ／ 平 1** | 凶占 **83.1%** |
| **朴素基线（全判凶）** | **172/207 = 83.1%** | 这是"零智能"的下限 |
| 引擎 M3 | **185/207 = 89.4%** | |
| **真实增量** | **+13 案 = +6.3 pp** | 185 − 172 ＝ 13 |
| ├ **凶案 recall** | **169/172 = 98.3%** | 几乎全对 |
| ├ **吉案 recall** | **16/34 = 47.1%** | **一半以上吉案被判凶** |
| └ 净账 | **+16 例吉案判对 ／ −3 例凶案判错** | ⇒ 净 **+13** |
| 引擎判凶率（trend 看跌 186/207） | **89.9%** | **比语料凶率还高 6.8pp** |

> ⇒ **「89.4%」里 83.1% 是语料底子，只有 6.3pp 是引擎挣的。**
> ⇒ 报这个数字时**必须并列 83.1%**，否则严重高估。

**分占类（M3）**：

| 类别 | 准确率 | 备注 |
|---|---|---|
| 疾病 | 100.0%（17/17） | ⚠️ 该类吉案极少 ⇒ 多半是"全判凶全对" |
| 官讼 | 100.0%（11/11） | 同上 |
| 婚姻 | 100.0%（3/3） | 样本 3，不可解读 |
| 家宅 | 97.4%（38/39） | |
| 功名 | 91.7%（55/60） | |
| 求财 | 85.7%（12/14） | |
| 其他 | 83.7%（36/43） | **≈ 朴素基线** |
| 出行 | 76.9%（10/13） | **低于基线** |
| **胎产** | **42.9%（3/7）** | **远低于基线（差）** |

⛔ **看分类准确率前必须先看该类吉案数** —— 否则"100%"会被误读成"很强"。

## 3. 🔴 硬伤一：M1 ≡ M2 ≡ M3 —— **消融对比是空的**

实测三方法**混淆矩阵逐案完全相同**：

| 方法 | 定义 | 准确率 | 混淆矩阵 |
|---|---|---|---|
| M1 | 原始引擎（无 caishen、无 holistic） | 89.4% | 完全相同 |
| M2 | 融合 + 求财类神（无 CBR） | 89.4% | 完全相同 |
| M3 | 融合 + 求财类神 + CBR（"完整"） | 89.4% | 完全相同 |
| M4 | 仅求财类神 | **14.5%** | 几乎全判吉（凶→吉 160） |

**探针实测（`_probe_signal_groups.py`，n=207）**：

| 检查项 | 结果 |
|---|---|
| `holistic_judgment` 键存在的案 | **0 / 207** |
| 实际产出 `caishen` 信号的案 | **0 / 207** |

**原因**：古例域**主动禁用** caishen（`DISABLE_CAISHEN=True`，注释「与 caishen 决裂：本库不注入任何看涨偏置」），
且古例路径不产出 `holistic_judgment` ⇒ **两个被"消融"的信号本就从未产出**。

⇒ **M1 ≡ M2 ≡ M3 是必然结果，不是巧合** —— 所谓「完整融合引擎 M3」在古例盲测中**没有内容**，
它等价于「原始引擎 M1」。**这三个"方法"的对比目前是自欺。**

⚠️ 连带发现：`M4 = 14.5%`（凶→吉 160）说明 `caishen_enhance`（求财类神）整套逻辑有**极强吉向偏置**；
它在 M2/M3 里被禁用而未污染，但**一旦启用就会毁掉判定** —— 这条要记牢。

## 4. 🟡 原「硬伤二」已被诊断推翻：占类规则**不是断链**，是**刻意收窄**

> ⚠️ **本报告初版把这一项写成「占类规则大面积空转 ⇒ 当前最大的免费提升空间」。诊断后**推翻**：**
> 结论错了，如实留档（详见 §4.3）。

| 官讼 `guansong` | 8 | 11 | 72.7% |

### 4.2 三成因分流（探针 `_diag_zhanlei_valence.py`，n=207）

| 成因 | 实测 |
|---|---|
| ① 占类名不一致（命名空间/归一化） | **0 案**（8 个占类全部 207/207 名称一致） |
| ② `_*_valence` 键缺失（上游未算） | **0 案**（键存在 207/207） |
| ③ 有键但 `score == 0`（条件未命中） | **全部**（求财 11／功名 43／家宅 12／疾病 8／出行 8／官讼 3／胎产 2／婚姻 1） |

⇒ **一条断链也没有** —— 链路完整、占类名对齐，低触发率**全部来自 valence 内部条件**。

### 4.3 为什么"低触发率"是**设计**而非缺陷

读实现（`engine/liuren_keti_bifa.extract_gongming_valence` 等）——条件写得极细，且**带历史 A/B 结论**：

```
# ---- G1: 临官帝旺临传（L4552：临官帝旺干支遇，爵禄峥嵘任帝都）----
# 2026-08-01 A/B 实证：正向信号在凶重语料(功名 37凶/10吉)误推吉，M3 87.2→84.8 负回归，
...
```

另有大量 **X* 判据**只在特定神煞组合下给分（如「朱雀值鬼**且非长生位**才判凶」），
以及**主动降级为记录层**（`score 0`）的分支（如「朱雀乘鬼但=长生学堂 → 不判凶」）。

⇒ 这是**「宁缺勿滥 + 已被 A/B 否决过放宽」**的结果，不是漏算。
**放宽的正向信号在凶重语料上会负回归**（G1 实测 87.2 → 84.8）。

### 4.4 结论（修正后）

- ❌ **不是**「最大的免费提升空间」；⛔ **不建议**去"修覆盖率"。
- ✅ 正确动作＝**把这个事实记档**，防止后人（含 AI）再把"触发率低"误读成"断链/漏算"而去做无用功。
- 主力信号覆盖 100%：`wangshuai`(621 条)｜`liuqin`(828)｜`tianjiang`(579)｜`keti`(207)｜`shen_sha`(207)｜
  `ba_sha`(91.3%)｜`changsheng`(36.7%)｜`sanchuan_kege`(22.2%)

## 5. 语料本身的偏倚 —— 差距的"地基"

- **真值分布 172 凶 ／ 34 吉 ／ 1 平**（凶 **83.1%**）。
- **来源偏倚**：古籍**被记录的多是应验的凶事**（祸事才值得立案流传）⇒ 吉案系统性缺失。
- ⇒ 在这批语料上算出的**任何**指标都带此偏倚；
  **真实择日场景的吉凶比例绝不可能是 83 : 17** ⇒ **指标不可直接外推**。
- ⇒ 也解释了为什么"吉案 recall 47.1%"是最刺眼的一栏：**吉案样本太少**，
  引擎在"吉"这一侧的判别力**实质上未被充分检验**。

---

## 6. 为什么「真实案例预测」必然更差 —— 四条机制

1. **输入多一层出错面**：盲测吃的是 PDF 直提的日干支/月将/时辰（干净）；
   真实预测要吃**用户录入 ＋ 节气 ＋ 真太阳时 ＋ 排盘管线**。
   —— 今天刚踩过：探针漏传 `ben_ming` 导致 **6 个子结构假 DIFF**；月建跨年 bug（每年 1/1~小寒前误判丑月）。
2. **输出维度不匹配**：盲测比**一个标量**（吉/凶/平）；
   用户实际消费的是**叙事**（宫位链／主线／tone／占类宜忌／旺衰应事／天将生克／喜忌×旺衰）——
   而这些层**全部不进评分链** ⇒ **M3 对它们零感知**，指标与交付物**脱节**。
3. **没有结果回填闭环**：A股域有 `stock_result_check.py` ＋ `weight_backfill` ＋ `backfill_snapshots`；
   **择日域没有**（只有 `leixiang_kb` 的类象统计）⇒ **真·盲测集不存在**。
4. **反复用同一测试集调参**：涉害口径、别责柔日、青龙·丑、今日的喜忌×旺衰……
   每次"修复"都拿 218 案投票（SOP O4「用古例语料投票」）⇒ 实质是**在测试集上训练**。

## 7. 今天的最新实证（同一问题的闭环）

L2568「喜则宜旺相，忌则宜休囚」：初测 δ1 比 δ0 **+7.2pp**（31.4%→38.6%）**看着有效**；
**朴素基线 83.1%** ⇒ 再查**分离度** ⇒ **四格全无分离度**（+1.1／+7.3／−0.7／−3.3 pp）⇒ 判为**偏置**。

> ⇒ **在"同源测试集"上都测不出分离度的特征，到了真实预测只会更差。**
> ⇒ 反过来也说明：**测试集上 +7pp 级别的"提升"极可能是噪音**。

## 8. 缩小差距的六条建议（按性价比排序）

| # | 动作 | 理由 | 成本 |
|---|---|---|---|
| ① | **报数规范**：任何准确率必须**并列朴素基线 ＋ 吉/凶案 recall ＋ 混淆矩阵** | 禁止单报 89.4% 造成高估 | 零（写进 SOP） |
| ② | **修「假消融」**：M1/M2/M3 要么让古例域真产出 holistic/caishen，要么**合并为一个方法** | 现在的对比是自欺 | 低 |
| ③ | ~~查占类规则空转~~ → **已查完并关闭** | **诊断推翻原判断**：不是断链、是刻意收窄（§4），放宽曾负回归 ⇒ ⛔ 不建议修覆盖率 | 已完成 |
| ④ | **建真盲测集**：新起的**真实用事日** ＋ 事后结果回填，**单独存库、与 218 案隔离**，定期跑 | 差别在于**有数字 vs 没数字** | 中（需长期） |
| ⑤ | **指标补校准**：`prob_up/prob_down` 未验 AUC／Brier | 档位准确率丢掉了概率信息 | 低 |
| ⑥ | **守底线**：古例结论**不外推**（含股票域、含真实择日） | 红线 | 零 |
