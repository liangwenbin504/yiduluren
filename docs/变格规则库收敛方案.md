* **项目**：仪度六壬择日系统

* **日期**：2026-09-01

* **状态**：📋 方案评审中（未启动实施）

* **适用范围**：`data/kege_bianjie_rules.json` + `engine/kege_atoms.py` 新增谓词

***

## 一、背景

变格引擎端到端巡检（2026-09-01）已在**引擎代码层**修复 4 处系统性断链（`env['guiren']` 缺失、丧门/吊客缺失、`'初'` 未解析、`_chuan_mu_ru_mu` 判据错），恒假谓词 13→8、真断链规则 76→43。

修复后**暴露**的是规则库层质量问题（非引擎 bug）：

| 现状                 | 数据                                  |
| ------------------ | ----------------------------------- |
| 规则总数               | 607 条（通用类 416 条）                    |
| 原子谓词               | 134 个                               |
| 贵人系规则判据过宽          | **37 条**，命中率 14.4%\~26.2%，互斥规则同课同命中 |
| 真断链（0 命中）占位/名实不符规则 | **43 条**（剔除 67 条 keti 依赖合理项后）       |

根因：早期规则库以"原文名 + 占位判据"方式批量铺条目，大量规则的**判据与毕法赋原文不符**——过宽型（条件过简，人人命中）与断链型（条件指向不可能事件，永不命中）并存。

## 三、收敛原则

1. **原文唯一**：判据以 `extracted_data/毕法赋_古籍注解_*_正文.txt` 为唯一基准（含《大六壬通解》对照），不采用现代演绎。
2. **宁缺毋滥**：原文明确才写判据；原文含糊的标记"待复核"，不写宽松兜底条件。
3. **判据可复核**：每条规则收敛后，新判据能以"谓词 → 原文落点"对应回原文句子。
4. **命中率回归**：过宽规则收敛后命中率显著下降（目标 <5% 或落入原文区间）；死规则复活为可满足；全量 8640 课扫描零异常。
5. **互斥校验**：顺治/逆治、差迭/加临、受克/塞鬼户等互斥对，收敛后同课同命中数必须为 0。
6. **不碰引擎架构**：只改 `kege_bianjie_rules.json` + 在 `kege_atoms.py` 新增/修正谓词，不动 `kege_bianjie_engine.py`。
